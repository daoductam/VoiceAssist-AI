# 1. Context

**Problem:**
Người dùng cần một ứng dụng trợ lý ảo di động cho phép đặt lịch, nhắc việc, tạo to-do, và đặt báo thức hoàn toàn bằng giọng nói tiếng Việt. App phải hoạt động offline-first với AI hybrid (online LLM + offline rule-based NLU), và thông báo nhắc lịch phải được tinh chỉnh ngôn ngữ tự nhiên theo tone do user chọn.

**Affected Modules:**
- `core/` — theme, router, constants, Vietnamese time parser utility
- `data/database/` — Drift SQLite tables, DAOs, database class
- `domain/` — models, enums, domain services (alarm, reminder, todo, notification)
- `features/voice/` — STT service, TTS service, voice pipeline orchestrator
- `features/ai/` — AI provider abstraction, offline rule-based NLU, response templates
- `features/home/` — main home screen with voice button
- `features/alarm/` — alarm list UI + create/edit
- `features/reminder/` — reminder list UI + create/edit
- `features/todo/` — to-do list UI
- `features/chat/` — conversation history UI
- `features/settings/` — tone settings, TTS settings
- `shared/` — reusable widgets, Riverpod providers

**Non-Goals (Phase 1):**
- Online LLM API integration (Groq/OpenAI/Gemini) — Phase 2
- Firebase Auth / Firestore cloud sync — Phase 2
- Google Calendar / Apple Calendar integration — Phase 3
- Home screen widget — Phase 3
- On-device LLM — removed from scope entirely
- Multi-language support (English) — future
- Wake word detection — future

# 2. Constraints

**Language:** `Dart (Flutter 3.x)`
**Architecture:** `Feature-first + Clean Architecture (presentation → domain → data)`
**State Management:** `Riverpod 2.x`

**Rules:**
- All data operations are local-first (SQLite via Drift)
- No network calls in Phase 1 — all AI processing is offline rule-based
- API key fields exist in settings but are non-functional until Phase 2
- No hardcoded strings for notification messages — all go through template engine
- `sync_status` field exists in DB tables but is unused until Phase 2

**Performance Budgets:**
- Voice pipeline (STT → NLU → Response → TTS): < 2s total on mid-range device
- App cold start: < 3s
- App size: < 30 MB
- Minimum OS: Android 8+ (API 26), iOS 14+

# 3. Conventions

**Naming:**
- Classes: `PascalCase` — e.g. `AlarmService`, `RuleBasedParser`
- Methods/variables: `camelCase` — e.g. `parseVietnameseTime()`, `currentAlarms`
- Constants: `camelCase` with `k` prefix for app constants — e.g. `kMaxTemplates`
- Files: `snake_case.dart` — e.g. `alarm_service.dart`, `vi_patterns.dart`
- Riverpod providers: `camelCase` ending with `Provider` — e.g. `alarmServiceProvider`

**Error Handling:**
- Strategy: domain-specific exception classes extending a base `AppException`
- Pattern: `throw AppException.alarmNotFound(id: alarmId)`
- Use `AsyncValue` from Riverpod for async state (loading/data/error)
- Validation: fail-fast at service method boundaries before DB operations

**Logging:**
- Library: `logger` package (pretty print in debug, minimal in release)
- Format: `logger.i('AlarmService.create: label=$label, time=$time')`
- Required at: entry of public service methods, catch blocks

**Testing:**
- Framework: `flutter_test` + `mocktail` for mocking
- Naming: `should_<expected>_when_<condition>` or group by method
- Example: `should_parseTime_when_givenVietnameseTimeString`
- Coverage: >= 80% on domain services, NLU parser, and time parser
- Widget tests for critical UI flows (voice button, alarm creation)

**Task Size:**
- Max 200 LOC per task (excluding tests)
- If a task exceeds this, split into subtasks

## Data Structure: `ParsedIntent`

```dart
ParsedIntent {
  intent:      IntentType    — identified intent from user speech
  entities:    Map<String, String>  — extracted entities (task, time, date, etc.)
  confidence:  double        — 0.0-1.0, how confident the parser is
  rawText:     String        — original transcribed text
}
```

## Data Structure: `Alarm`

```dart
Alarm {
  id:          String        — UUID, auto-generated, immutable
  time:        String        — HH:mm format, non-blank
  label:       String        — max 255 chars, default = ""
  repeatDays:  List<int>     — 1=Mon..7=Sun, empty = one-time
  sound:       String        — sound asset name, default = "default"
  isActive:    bool          — default = true
  createdAt:   DateTime      — set on creation, immutable
  updatedAt:   DateTime      — updated on every mutation
  syncStatus:  SyncStatus    — default = pending
}
```

## Data Structure: `Reminder`

```dart
Reminder {
  id:          String        — UUID, auto-generated, immutable

  repeat:      RepeatType    — default = once
  isCompleted: bool          — default = false
  tone:        ToneStyle     — inherits from user settings
  createdAt:   DateTime      — set on creation, immutable
  updatedAt:   DateTime      — updated on every mutation
  syncStatus:  SyncStatus    — default = pending
}
```

## Data Structure: `Todo`

```dart
Todo {
```

## Interface: `IntentParser`

```dart
IntentParser.parse(text: String): ParsedIntent
  - pre: text is non-blank
  - post: returns ParsedIntent with intent != null; confidence >= 0.0
  - throws: ArgumentError when text is blank
```

## Interface: `VietnameseTimeParser`

```dart
VietnameseTimeParser.parse(text: String, referenceTime: DateTime): DateTime?
  - pre: text is non-blank
  - post: returns DateTime if time expression found, null otherwise
  - never throws — returns null for unparseable input

VietnameseTimeParser.parseTimeOfDay(text: String): TimeOfDay?
  - pre: text is non-blank
  - post: returns TimeOfDay if time-of-day expression found, null otherwise
```

## Interface: `ResponseGenerator`

```dart
ResponseGenerator.generate(context: ResponseContext): String
  - pre: context.tone is valid ToneStyle; context.eventTitle is non-blank
  - post: returns non-blank natural language string with template variables resolved
  - never throws — falls back to simple template on error

ResponseGenerator.generateAlarmGreeting(tone: ToneStyle, taskCount: int): String
  - pre: taskCount >= 0
  - post: returns morning greeting string with task count embedded
```

## Interface: `AlarmService`

```dart
AlarmService.create(alarm: Alarm): Future<Alarm>
  - pre: alarm.time is valid HH:mm
  - post: alarm saved to DB + local notification scheduled; returns saved alarm
  - throws: AppException.invalidTime when time format invalid

AlarmService.delete(id: String): Future<void>
  - pre: id is non-blank
  - post: alarm removed from DB + scheduled notification cancelled
  - throws: AppException.notFound when id doesn't exist

AlarmService.toggle(id: String, isActive: bool): Future<Alarm>
  - pre: id exists in DB
  - post: alarm.isActive updated; notification scheduled/cancelled accordingly

AlarmService.getAll(): Future<List<Alarm>>
  - post: returns all alarms ordered by time ascending

AlarmService.watchAll(): Stream<List<Alarm>>
  - post: emits updated list whenever alarms table changes
```

## Interface: `ReminderService`

```dart
ReminderService.create(reminder: Reminder): Future<Reminder>
  - pre: reminder.title non-blank; reminder.remindAt is future
  - post: saved to DB + notification scheduled
  - throws: AppException.invalidReminder when validation fails

ReminderService.complete(id: String): Future<void>
  - pre: id exists
  - post: isCompleted = true; scheduled notification cancelled

ReminderService.delete(id: String): Future<void>
  - post: removed from DB + notification cancelled

ReminderService.getUpcoming(): Future<List<Reminder>>
  - post: returns incomplete reminders ordered by remindAt ascending

ReminderService.watchAll(): Stream<List<Reminder>>
```

## Interface: `TodoService`

```dart
TodoService.create(todo: Todo): Future<Todo>
  - pre: todo.title non-blank
  - post: saved to DB

TodoService.toggle(id: String): Future<Todo>
  - pre: id exists
  - post: isCompleted toggled

TodoService.delete(id: String): Future<void>

TodoService.getAll(): Future<List<Todo>>
  - post: returns all todos, incomplete first, then by priority

TodoService.watchAll(): Stream<List<Todo>>
```

## Interface: `NotificationService`

```dart
NotificationService.initialize(): Future<void>
  - post: notification channels created, permissions requested

NotificationService.scheduleReminder(id: String, title: String, body: String, scheduledAt: DateTime): Future<void>
  - pre: scheduledAt is future; id is unique
  - post: local notification scheduled at exact time

NotificationService.scheduleAlarm(id: String, time: TimeOfDay, label: String, repeatDays: List<int>): Future<void>
  - post: alarm notification scheduled (daily/weekly/one-time)

NotificationService.cancel(id: String): Future<void>
  - post: scheduled notification cancelled if exists; no-op if not found
```

## Interface: `VoicePipeline`

```dart
VoicePipeline.startListening(): Future<void>
  - pre: microphone permission granted
  - post: STT engine active, partial results emitted via stream
  - throws: AppException.micPermissionDenied

VoicePipeline.stopListening(): Future<String>
  - post: STT engine stopped, final transcribed text returned

VoicePipeline.processCommand(text: String): Future<VoiceResult>
  - pre: text is non-blank
  - post: intent parsed → action executed → natural response generated
  - returns: VoiceResult(responseText, actionTaken, intent)

VoicePipeline.speak(text: String): Future<void>
  - pre: TTS enabled in settings
  - post: text spoken aloud via TTS engine
```

## Data Structure: `VoiceResult`

```dart
VoiceResult {
  responseText:  String      — natural language response to speak/display
  actionTaken:   bool        — true if a domain action was executed
  intent:        IntentType  — what intent was detected
  createdEntity: dynamic?    — the alarm/reminder/todo created, if any
}
```

## Data Structure: `ResponseContext`

```dart
ResponseContext {
  tone:        ToneStyle     — user's selected tone
  eventTitle:  String        — name of the event/reminder
  time:        String        — formatted time string
  remaining:   String        — time remaining (e.g. "15 phút")
  greeting:    String        — time-of-day greeting (sáng/trưa/chiều/tối)
  taskCount:   int           — number of tasks today
  type:        String        — "reminder" | "alarm" | "confirmation"
}
```

# 5. Target Architecture

**Components:**
- `VoicePipeline` — orchestrates the full STT → NLU → Action → Response → TTS flow
- `SttService` — wraps `speech_to_text` package for Vietnamese STT
- `TtsService` — wraps `flutter_tts` package for Vietnamese TTS
- `RuleBasedParser` — offline intent parser using Vietnamese regex patterns
- `VietnameseTimeParser` — extracts date/time from Vietnamese natural language
- `ActionRouter` — maps parsed intents to domain service method calls
- `ResponseGenerator` — generates natural language responses using tone templates
- `AlarmService` / `ReminderService` / `TodoService` — domain CRUD + notification scheduling
- `NotificationService` — schedules/cancels local notifications and alarms
- `AppDatabase` (Drift) — SQLite database with tables and DAOs

**Interaction Flow:**

```
User taps mic button
  → VoicePipeline.startListening()
    → SttService.start(locale: "vi-VN") → Stream<String> (partial results)

User stops speaking
  → VoicePipeline.stopListening() → finalText: String

  → VoicePipeline.processCommand(finalText)
    → RuleBasedParser.parse(finalText) → ParsedIntent
      → VietnameseTimeParser.parse(entities["time"]) → DateTime?

    → ActionRouter.route(parsedIntent)
      [setAlarm]    → AlarmService.create(alarm)
                    → NotificationService.scheduleAlarm(...)
      [setReminder] → ReminderService.create(reminder)
                    → NotificationService.scheduleReminder(...)
      [addTodo]     → TodoService.create(todo)
      [querySchedule] → ReminderService.getUpcoming() + AlarmService.getAll()
      [unknown]     → responseText = "Xin lỗi, tôi chưa hiểu..."

    → ResponseGenerator.generate(context, tone) → responseText

    → ConversationLogDao.insert(log)

  ← VoiceResult(responseText, actionTaken, intent)

  → TtsService.speak(responseText)  // if TTS enabled
  → UI updates chat history
```

**Notification Trigger Flow:**

```
Scheduled time arrives
  → NotificationService fires local notification
    → ResponseGenerator.generate(context) → natural language body
    → Show push notification with natural text + TTS read-aloud (if foreground)
```

**Key Decisions:**
- `VoicePipeline` is the single orchestrator — UI only talks to VoicePipeline, never directly to STT/NLU/TTS
- `RuleBasedParser` is stateless and pure — easy to test with string inputs
- `VietnameseTimeParser` is a separate utility — reusable, independently testable
- `ResponseGenerator` is template-based with randomization — no two responses are identical
- All services use Drift `watch` streams → UI auto-updates via Riverpod
- `ActionRouter` is the only class that knows about all domain services — decouples NLU from domain
- Notification body text is generated at schedule time — not at display time — to avoid needing app context when notification fires
