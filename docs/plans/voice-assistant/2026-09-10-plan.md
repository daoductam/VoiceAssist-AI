# 1. Context

**Problem:**
Người dùng cần một ứng dụng trợ lý ảo di động cho phép đặt lịch, nhắc việc, tạo to-do, và đặt báo thức hoàn toàn bằng giọng nói tiếng Việt. App phải hoạt động offline-first với AI hybrid (online LLM + offline rule-based NLU), và thông báo nhắc lịch phải được tinh chỉnh ngôn ngữ tự nhiên theo tone do user chọn.

**Affected Modules:**
- `core/` — theme, router, constants, Vietnamese time parser utility
- `data/database/` — Drift SQLite tables, DAOs, database class
- `domain/` — models, enums, domain services (alarm, reminder, todo, notification)
- `features/voice/` — STT service, TTS service, voice pipeline orchestrator
- `features/ai/` — AI provider abstraction, offline rule-based NLU, response templates
- `features/home/` — main home screen with voice button
- `features/alarm/` — alarm list UI + create/edit
- `features/reminder/` — reminder list UI + create/edit
- `features/todo/` — to-do list UI
- `features/chat/` — conversation history UI
- `features/settings/` — tone settings, TTS settings
- `shared/` — reusable widgets, Riverpod providers

**Non-Goals (Phase 1):**
- Online LLM API integration (Groq/OpenAI/Gemini) — Phase 2
- Firebase Auth / Firestore cloud sync — Phase 2
- Google Calendar / Apple Calendar integration — Phase 3
- Home screen widget — Phase 3
- On-device LLM — removed from scope entirely
- Multi-language support (English) — future
- Wake word detection — future

# 2. Constraints

**Language:** `TypeScript (React Native / Expo)`
**Architecture:** `Feature-first + Clean Architecture (presentation → domain → data)`
**State Management:** `Zustand`

**Rules:**
- All data operations are local-first (SQLite via `expo-sqlite`)
- No network calls in Phase 1 — all AI processing is offline rule-based
- API key fields exist in settings but are non-functional until Phase 2
- No hardcoded strings for notification messages — all go through template engine
- `sync_status` field exists in DB tables but is unused until Phase 2

**Performance Budgets:**
- Voice pipeline (STT → NLU → Response → TTS): < 2s total on mid-range device
- App cold start: < 3s
- App size: < 35 MB
- Minimum OS: Android 8+ (API 26), iOS 14+

# 3. Conventions

**Naming:**
- Classes/Interfaces/Types/Components: `PascalCase` — e.g. `AlarmService`, `RuleBasedParser`, `HomeScreen`
- Methods/variables/hooks: `camelCase` — e.g. `parseVietnameseTime()`, `useAlarmStore`
- Constants: `SCREAMING_SNAKE_CASE` or `kCamelCase` — e.g. `MAX_TEMPLATES`
- Files: `snake_case.ts` for logic / `PascalCase.tsx` for React components — e.g. `alarm_service.ts`, `HomeScreen.tsx`
- Stores: `use<Entity>Store` — e.g. `useAlarmStore`

**Error Handling:**
- Strategy: domain-specific error classes extending a base `AppException`
- Pattern: `throw new AppException('ALARM_NOT_FOUND', 'Báo thức không tồn tại')`
- State handling: Zustand stores manage `{ data, loading, error }`
- Validation: fail-fast at service method boundaries before DB operations

**Logging:**
- Library: lightweight console logger with debug/info/error tags
- Format: `[AlarmService.create] label=${label}, time=${time}`
- Required at: entry of public service methods, catch blocks

**Testing:**
- Framework: `jest` + `@testing-library/react-native`
- Naming: `should_<expected>_when_<condition>`
- Example: `should_parseTime_when_givenVietnameseTimeString`
- Coverage: >= 80% on domain services, NLU parser, and time parser

**Task Size:**
- Max 200 LOC per task (excluding tests)
- If a task exceeds this, split into subtasks

# 5. Target Architecture

**Components:**
- `VoicePipeline` — orchestrates the full STT → NLU → Action → Response → TTS flow
- `SttService` — wraps `speech_to_text` package for Vietnamese STT
- `TtsService` — wraps `flutter_tts` package for Vietnamese TTS
- `RuleBasedParser` — offline intent parser using Vietnamese regex patterns
- `VietnameseTimeParser` — extracts date/time from Vietnamese natural language
- `ActionRouter` — maps parsed intents to domain service method calls
- `ResponseGenerator` — generates natural language responses using tone templates
- `AlarmService` / `ReminderService` / `TodoService` — domain CRUD + notification scheduling
- `NotificationService` — schedules/cancels local notifications and alarms
- `AppDatabase` (Drift) — SQLite database with tables and DAOs

**Interaction Flow:**

```
User taps mic button
  → VoicePipeline.startListening()
    → SttService.start(locale: "vi-VN") → Stream<String> (partial results)

User stops speaking
  → VoicePipeline.stopListening() → finalText: String

  → VoicePipeline.processCommand(finalText)
    → RuleBasedParser.parse(finalText) → ParsedIntent
      → VietnameseTimeParser.parse(entities["time"]) → DateTime?

    → ActionRouter.route(parsedIntent)
      [setAlarm]    → AlarmService.create(alarm)
                    → NotificationService.scheduleAlarm(...)
      [setReminder] → ReminderService.create(reminder)
                    → NotificationService.scheduleReminder(...)
      [addTodo]     → TodoService.create(todo)
      [querySchedule] → ReminderService.getUpcoming() + AlarmService.getAll()
      [unknown]     → responseText = "Xin lỗi, tôi chưa hiểu..."

    → ResponseGenerator.generate(context, tone) → responseText

# 5. Target Architecture

**Components:**
- `VoicePipeline` — orchestrates the full STT → NLU → Action → Response → TTS flow
- `SttService` — wraps native speech recognition (`@react-native-voice/voice`) for Vietnamese STT
- `TtsService` — wraps `expo-speech` for Vietnamese TTS
- `RuleBasedParser` — offline intent parser using Vietnamese regex patterns
- `VietnameseTimeParser` — extracts date/time from Vietnamese natural language
- `ActionRouter` — maps parsed intents to domain service calls
- `ResponseGenerator` — generates natural language responses using tone templates
- `AlarmService` / `ReminderService` / `TodoService` — domain CRUD + notification scheduling
- `NotificationService` — schedules/cancels local notifications via `expo-notifications`
- `AppDatabase` — SQLite database with tables and DAOs via `expo-sqlite`
- `Zustand Stores` (`useAlarmStore`, `useReminderStore`, `useTodoStore`, `useSettingsStore`) — reactive UI state management

**Interaction Flow:**

```
User taps mic button
  → VoicePipeline.startListening()
    → SttService.start("vi-VN") → partial results callback

User stops speaking
  → VoicePipeline.stopListening() → finalText: string

  → VoicePipeline.processCommand(finalText)
    → RuleBasedParser.parse(finalText) → ParsedIntent
      → VietnameseTimeParser.parse(entities.time) → Date | null

    → ActionRouter.route(parsedIntent)
      [setAlarm]      → AlarmService.create(alarm)
                      → NotificationService.scheduleAlarm(...)
      [setReminder]   → ReminderService.create(reminder)
                      → NotificationService.scheduleReminder(...)
      [addTodo]       → TodoService.create(todo)
      [querySchedule] → ReminderService.getUpcoming() + AlarmService.getAll()
      [unknown]       → responseText = "Xin lỗi, tôi chưa hiểu..."

    → ResponseGenerator.generate(context, tone) → responseText

    → ConversationLogDao.insert(log)

  ← VoiceResult(responseText, actionTaken, intent)

  → TtsService.speak(responseText)  // if TTS enabled
  → UI updates chat history
```

**Notification Trigger Flow:**

```
Scheduled time arrives
  → expo-notifications fires local notification
    → ResponseGenerator.generate(context) → natural language body
    → Show notification with natural text + voice alert
```

**Key Decisions:**
- `VoicePipeline` is the single orchestrator — UI only talks to VoicePipeline, never directly to STT/NLU/TTS
- `RuleBasedParser` is stateless and pure — easy to test with string inputs
- `VietnameseTimeParser` is a separate utility — reusable, independently testable
- `ResponseGenerator` is template-based with randomization — no two responses are identical
- All domain stores use Zustand — minimal boilerplate, high performance on React Native
- `ActionRouter` is the only class that knows about all domain services — decouples NLU from domain
- Notification body text is generated at schedule time — to avoid needing app execution when notification fires

# 9. Edge Cases

| # | Scenario | Expected Behavior | Handled In |
|---|----------|-------------------|------------|
| 1 | Create alarm with duplicate time | Allowed — different IDs, both active | TASK-002 |
| 2 | Delete non-existent ID | No-op, no exception thrown | TASK-002 |
| 3 | Mixed Vietnamese + English input | Best-effort parse, low confidence (< 0.5) | TASK-003 |
| 4 | Ambiguous time "3 giờ" without AM/PM | Default to nearest future time (if now 14:00, → 15:00) | TASK-003 |
| 5 | Create reminder 1 minute in future | Accepted and scheduled | TASK-004 |
| 6 | Delete alarm that's currently ringing | Alarm stopped + deleted from DB | TASK-004 |
| 7 | Schedule notification < 1 min from now | Still schedules (fires immediately) | TASK-005 |
| 8 | App backgrounded/killed | Notifications still fire via OS scheduler | TASK-005 |
| 9 | Very long event title (200+ chars) | Truncated with "..." in template | TASK-006 |
| 10 | taskCount = 0 (no tasks today) | "Hôm nay trống lịch" variant | TASK-006 |
| 11 | STT returns empty (user silent) | Return "Tôi không nghe rõ, bạn nói lại nhé" | TASK-007 |
| 12 | TTS called while already speaking | Stop previous speech, start new | TASK-007 |
| 13 | Service throws during action | Catch, return user-friendly error response | TASK-008 |
| 14 | User denies microphone permission | Show permission explanation dialog | TASK-009 |
| 15 | Rapid double-tap voice button | Debounce — ignore second tap while processing | TASK-009 |
